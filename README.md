# Two Plates

A weekly high-protein meal planner for two people. It picks 5–7 dinners (each one also covers the next day's lunch), shows protein and calories per person, and builds a combined grocery list you can export to Excel. The Today tab also tracks water per person: a "Did you drink water?" yes/no check-in at 9am, noon, 3pm, 6pm and 9pm (nothing after 10pm) plus an optional glass counter, and a 10pm check-in asking about coffees, teas, milks and shakes. Check-ins arrive as push notifications even when the app is closed (see `supabase/reminders-setup.sql`); tapping one opens the app on the Yes/No question and daily/weekly summaries keep check-in answers separate from glass counts.

Allergies and dislikes can be excluded in Settings: dishes listing those ingredients (or direct forms of the same food, like peanut butter for peanuts) are skipped by shuffle, swaps and the dish picker, and anything already in the week gets a warning badge. The app checks its own recipe ingredient lists — it can't see inside packaged goods or track cross-contact.

There's no build step. It's plain HTML, CSS and JavaScript modules, and everything runs in the browser.

## What's where

| Path | What it is |
| --- | --- |
| `data/ingredients.js` | Ingredient catalog: nutrition per 100 g, grocery section, pantry flag. **Every dish's macros come from here.** |
| `data/recipes/*.js` | The dish library, one file per cuisine. Each row: `[name, minutes, "ingredient qty, …", "tags"]`, with quantities for 4 standard servings. |
| `data/regulars.js` | Dishes you already cook often ("Regular" badge, picked more often until rated). |
| `data/shopping-habits.js` | What you actually buy (learned from receipts), shown on the list instead of rough amounts, plus every-week staples. |
| `js/planner.js` | Weekly picking rules (veg quota, cuisine weights, variety, time limits) and per-person maths. |
| `js/grocery.js` | Combines and scales ingredients into the shopping list. |
| `js/export.js` | Excel export (shopping list, pantry check, menu with YouTube links). |
| `js/sync.js` | Optional live sync between phones through Supabase. |
| `js/water.js` | Water goal helper and the fixed-time check-in slots, answers and summaries. |
| `js/push.js` | Subscribe this phone for push reminders (even when the app is closed). |
| `supabase/functions/water-reminders` | Edge function that sends the push notifications. |
| `supabase/reminders-setup.sql` | One-time SQL: subscriptions table, dedupe log, cron job (every 5 min). |
| `js/app.js` | The screens. |
| `data/recipes.json` | Plain dish details generated by `node tools/build-json.mjs` (re-run after editing recipes); read by the scheduled tasks. |
| `tools/validate.mjs` | Checks the recipe data: `node tools/validate.mjs` (add `--all` to list every dish's numbers). |

### Adding a dish

Add a row to the right file in `data/recipes/`, using ingredient ids from `data/ingredients.js`, then run `node tools/validate.mjs`. If you need a new ingredient, add it to the catalog first with its nutrition per 100 g.

## Run it on your computer

```bash
python3 -m http.server 8642
```

Then open http://localhost:8642.

## Put it on your phones (GitHub Pages)

1. Create a new GitHub repository (e.g. `two-plates`) and push this folder to it.
2. In the repository, go to **Settings → Pages → Build and deployment**, choose **Deploy from a branch**, then pick `main` and `/ (root)`.
3. After a minute it's live at `https://<your-username>.github.io/two-plates/`.
4. On each iPhone, open that link in Safari and tap **Share → Add to Home Screen**.

## Live sync between both phones (Supabase, free)

Without this step, each phone keeps its own plan. With it, a shuffle, swap or ticked grocery item on one phone shows up on the other within a second or two.

1. Sign up at https://supabase.com and create a new project (the free tier is plenty). Pick the Sydney region.
2. Open **SQL Editor**, paste this and click **Run**:

   ```sql
   create table public.meal_state (
     id text primary key,
     data jsonb not null,
     updated_at timestamptz not null default now()
   );
   alter table public.meal_state enable row level security;
   create policy "household read/write" on public.meal_state
     for all to anon using (true) with check (true);
   grant select, insert, update on public.meal_state to anon;
   alter publication supabase_realtime add table public.meal_state;
   ```

3. Go to **Project Settings → Data API** and copy the **Project URL**, then **Project Settings → API Keys** and copy the **Publishable key** (`sb_publishable_…`; older projects show it as the legacy **anon public** key starting `eyJ`). Never use a secret / service_role key.
4. In the app, open **Settings → Sync between phones**. Paste the URL and the key, tap **New** to make a household code, then tap **Connect**.
5. On the second phone, enter the same three values (copy the household code across).

Privacy note: the anon key is designed to be public, and the policy above lets anyone who has both the key and your project URL read or write the table. The only thing stored there is your meal plan and settings, so this is a reasonable trade-off for a personal app. Don't put the key in the code or the repository; enter it in the app on each phone.

## Changing the numbers

- **Targets, shake/breakfast/snacks, portion sizes:** Settings → People. A portion of 1.25× means 1.25 standard servings per meal.
- **Veg quota, Indian veg count, time limit, cuisine mix:** Settings → Planning rules.
- **Pantry staples:** Settings → Pantry staples, or tap "Have it" / "Need to buy" on the grocery list.
- **A dish you don't like:** tap the eye-slash icon on the Recipes tab and it's never suggested again (undo under "Hidden").

## Groceries beyond meals and guests

Groceries now has editable extras with amounts and sections (drinks, snacks/breakfast, food, household, other). These persist across reshuffles and new weeks until explicitly deleted. Existing name-only extras still load.

Guests & parties keeps occasions separate from weekly meals. Add a name/headcount, then library recipes with servings per dish. Ingredients are scaled from the existing four-serving library and merged into groceries with provenance. Changing the headcount does not silently change servings already set for dishes. Edit servings on each dish directly. Changed party quantities untick the affected shopping items so an old tick does not imply a larger amount was bought. Include/exclude an occasion without deleting it. Custom recipes and party extras accept one ingredient per line, with user-entered amounts after `|`; no quantities are generated from an arbitrary dish name.

## Selected-dish prep (first version)

Week → Plan my prep starts with no dishes selected. Tick the dishes to work on, choose a prep date and available active minutes (60 = one hour). Matching prep actions for the same ingredient combine across selected dishes. Editable task estimates are planning defaults, not measured timings. Cook dates default to the prep date. Fresh tasks are offered only on the cook date; dry measuring may be done earlier. Done checks are keyed to the day and plan.

`data/prep-guides.js` contains adapted, sourced outlines for the five dishes planned on 7 November 2026. These are not verified original methods for the lighter library variants; each guide names the ingredient differences and links its source. Other recipes are clearly marked as not reviewed, without invented steps. Sides may still require a separate method. Food safety links point to NSW Food Authority; no multi-day raw meat or cooked-rice batch plan is generated.

New state fields (`occasions`, `prep`) live in the existing shared meal-state JSON, so they use the current phone sync and backups. No database changes or new services are needed. Existing sync is whole-document last-write-wins except for daily logs; simultaneous edits to groceries from two phones are not conflict-free.

Tests: `node test-features.mjs`; `node tools/validate.mjs`.
